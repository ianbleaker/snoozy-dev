# Changelog

## v1.2.0 — 2026-11-13
### New
- The GitHub-workflow skills (`/next-task`, `/log-task`, `/write-plan`, `/implement-plan`, `/batch-tasks`) work in Claude Code cloud sessions through `gh api` REST calls. Skills that need a local machine (`/deploy`, `/stage-preview`, `/merge-preview`, `/sweep-tasks`, `/go-public`) stop with a clear message, `/doc-release` stops after the cut, and `/onboard` prints its repo-settings commands instead of running them. (Cloud sessions, Task flow) [`5bcbaef`](https://github.com/ianbleaker/snoozy-dev/commit/5bcbaeff24d2e392228ca2bfcb2cde166d489c28)
- New `release.stableBranch` setting in `doc-changelog.json`: `release.sh --publish` fast-forwards that branch to each published release commit (it never force-pushes). snoozy-dev sets it to `stable`. (Doc changelog) [`ab2e11a`](https://github.com/ianbleaker/snoozy-dev/commit/ab2e11a9cb62f2b40b3506caef775a2aff0d6241)
- The plugin now offers `/snoozy-dev:onboard` at session start when a repo isn't set up or its setup is behind the plugin, and remembers a decline per repo. Each repo keeps its verify commands and an onboard schema stamp in a tracked `.snoozy-dev.json`; the plugin runs the edit and Stop verify hooks from it and feeds failures back to Claude, which the old per-repo hooks never did, and the pre-commit gate and CI run its `verify.gate`. The Claude-free and md-unwrap hooks also ship in the plugin now, so they run in cloud too: re-run `scripts/install-plugin.sh` after updating to remove their old `~/.claude/settings.json` entries. (Setup and onboarding) [`fa2ba72`](https://github.com/ianbleaker/snoozy-dev/commit/fa2ba728e95f73ac2f3dfc40b1e2a757d03b8791)
- Projects record which version of the deploy convention they follow as a `- Convention: vps-systemd@2` line (or `none`) in CLAUDE.md's `## Deploy` section. `/onboard` detects it and fills it in after you confirm. The session-start check then offers a draft migration issue, with the migration notes, when a project is behind the plugin's convention, and flags drift such as a removed `deploy/` folder or a new `Dockerfile`. (Preview and deploy, Setup and onboarding) [`9e0f709`](https://github.com/ianbleaker/snoozy-dev/commit/9e0f709ba78481c0b208de5bd6d0d58782fa86a3)
### Changed
- `/deploy` and `/stage-preview` now SSH in as your own non-root account and run `deploy.sh` as a per-instance `<repo>-deployer` user (`sudo -n -u`), so repo code never runs as root. Projects need `deploy/setup.sh` re-run on the host first (see `deploy-scripts.md`, "Privilege model" and "Host access"). `## Deploy` lines are now `- Key: value` list items (the bare form still works), `Preview URL:` takes a `{host}` placeholder resolved from your own `~/.ssh/config`, `Preview path:` is optional, and the projects root comes from `SNOOZY_PROJECTS_DIR` (default `~/development`). Parsing lives in the new `deploy-config.sh` helper. (Preview and deploy, Setup and onboarding) [`40f4bc5`](https://github.com/ianbleaker/snoozy-dev/commit/40f4bc5d41ca7e9c2d08a1bbb255b610f6f3a437)
- `scripts/install-plugin.sh` installs snoozy-dev from the GitHub marketplace's `stable` branch (the latest release) instead of a local checkout, and turns on marketplace auto-update, so every machine picks up each new release at startup. Re-running it migrates an existing local-directory install. Cloud environments use a one-line `curl … | bash` setup script. To try unreleased skills, use `claude --plugin-dir ~/development/snoozy-dev/plugins/snoozy-dev`. (Setup and onboarding) [`ab2e11a`](https://github.com/ianbleaker/snoozy-dev/commit/ab2e11a9cb62f2b40b3506caef775a2aff0d6241)
### Fixed
- `scripts/install-plugin.sh` checks that the branch it installs from exists on GitHub before changing anything. Before, migrating to `stable` before the first release removed the old marketplace, which uninstalled the plugin, and only then failed to add the new one. (Setup and onboarding) [`0a2b577`](https://github.com/ianbleaker/snoozy-dev/commit/0a2b577141c9c5d19062338b64230a2665a77ab1)
